# 보안 정책

## 지원 범위

현재 `main` 브랜치를 기준으로 보안 문제를 수정한다. 정식 릴리스와 장기 지원 버전 정책은 아직
운영하지 않는다.

## 취약점과 비밀정보 신고

민감한 내용은 공개 Issue에 올리지 않는다. Organization 관리자에게 비공개 채널로 저장소,
영향 범위, 재현 방법과 노출된 키 종류를 전달한다.

API 키가 커밋되었거나 로그에 노출되었다면 파일 삭제만으로 끝내지 않는다.

1. 해당 공급자에서 키를 즉시 폐기한다.
2. 새 키를 Secret Manager 또는 로컬의 무시된 `.env`에 발급한다.
3. Git 기록과 CI 로그의 노출 범위를 확인한다.
4. 영향을 받은 호출과 비용을 감사한다.

## 기본 원칙

- 실제 문서와 API 키는 Git에 저장하지 않는다.
- 서버가 tenant, wiki, actor와 입력 경로를 결정한다.
- `restricted` 문서는 외부 LLM에 전송하지 않는다.
- retrieval 결과를 프롬프트에 넣기 전에 접근 권한을 검사한다.
- 자연어 문서 변경은 승인과 낙관적 동시성 검사를 거친다.
